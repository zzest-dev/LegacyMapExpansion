# Сетевая совместимость карты

Обновлённые Windows- и Linux-архивы выпуска 1.0.0 используют сетевой протокол карты 1. Он обязателен при включённом LegacyMapExpansion. Основной BigCityLegacy не требует изменений: проверка встроена в плагин карты и работает поверх штатного UNet.

## Порядок подключения

1. После установления транспортного соединения сервер создаёт состояние с индивидуальным случайным nonce и отправляет запрос подтверждения.
2. Клиент с новым плагином сообщает протокол, nonce, готовность ресурсов и идентификатор карты. Идентификатор вычисляется из бинарника MapPro, совместимости, таблицы материалов земли, общего resources.lock.json и версии протокола/релиза. Общий манифест содержит хеши исходных ассетов и обоих платформенных бандлов: Windows и Linux одной поставки совпадают, хотя байты их собственных AssetBundle различаются.
3. Сервер разрешает Ready/AddPlayer только после проверки. До этого не создаются NetConnect/игрок и не вызывается штатная инициализация персонажа. Отложенные Ready/AddPlayer не являются разрешением и могут быть продолжены только после успешного ответа.
4. При несовпадении протокола, другой карте или ошибке загрузки клиент отклоняется. Если плагина нет либо установлена старая DLL без протокола, сервер отключает соединение по таймауту.
5. Каждые 30 секунд сервер повторяет проверку с новым nonce. Если плагин перестал отвечать, соединение закрывается. Повторный ответ на старый nonce не продлевает допуск.

Идентификатор карты и отказ не заменяют проверку владения сетевыми объектами и обычные проверки игры. Это барьер совместимости для обычных клиентов, а не античит и не криптографическое доказательство наличия DLL: специально изменённый клиент может имитировать протокол.

## Почему фоллбэк не обходит проверку

Проверка стоит на игровом сервере, а не только в интерфейсе поиска. Она блокирует UNet Ready, оба входа OnServerAddPlayer и дополнительно Cmd_SetPrivateID/InitInputControl. Поэтому подключение через список серверов, прямой IP или альтернативный адрес не создаёт игрока без допуска. На сервере состояние связано с объектом NetworkConnection, а не только с IP или числовым ID соединения.

Плагин также откладывает обычный OnClientConnect до положительного ответа. Если сервер не поддерживает проверку, клиент с новой картой не продолжает вход на старую карту. При ошибке используются существующий NativeErrorDialog из BigCityLegacy, если он доступен, затем собственное окно плагина и запись в журнал. Для клиента вообще без плагина остаётся стандартное сообщение игры об отключении; серверный журнал содержит точную причину.

Если включённый плагин карты не смог подготовить ресурсы, запуск dedicated-сервера завершается с ошибкой, а StartServer не разрешается. Молчаливый переход сервера на штатную карту не используется. Явное `General.Enabled = false` отключает расширение и его проверку на следующем запуске, то есть сервер становится сервером штатной карты.

## Пинг и настройки

Штатный UDP-ответ на порту `игровой порт + 1` сохраняет исходные поля и дополнительно содержит:

```text
lmeRequired:1|lmeReady:1|lmeProtocol:1|lmeVersion:1.0.0|lmeMap:<sha256>|
```

При неготовой карте `lmeReady` равен 0. Старые обработчики пинга могут игнорировать дополнительные поля; решение о допуске всегда принимает игровой сервер через UNet, а не UDP-пинг. Новые сообщения используют ID 27920–27922 и надёжный штатный канал.

Конфигурация: `BepInEx/config/com.bigcitylegacy.map1018.cfg`, раздел `[Network]`:

```ini
HandshakeTimeoutSeconds = 8
HeartbeatIntervalSeconds = 30
```

Настройки применяются при запуске: таймаут 3–30 секунд, период heartbeat 15–120 секунд. Не нужно открывать новый TCP/UDP порт: используются существующие игровые соединения и штатный порт пинга.

## Обновление

Остановить сервер и клиенты, обновить DLL из актуальных архивов существующего релиза v1.0.0. Число 1.0.0 сохранено, поэтому для совместимости ориентироваться на обновлённые архивы и сообщения `Map admission enabled`/`Map handshake accepted` в логе, а не только на отображаемую версию. Windows-клиенту нужна Windows-DLL, Linux-серверу Linux-DLL. Их идентификаторы карты в логе должны совпадать.

## Проверка

`dotnet build tests/AdmissionTests.csproj -c Release`, затем `tests/bin/Release/AdmissionTests.exe`: идентификаторы, несовпадения, таймауты, nonce, heartbeat, UNet-сериализация и совместимость полей UDP-пинга.

`tools/prepare_admission_tests.ps1` создаёт изолированный проект Unity 2019.1.8f1. Запуск с `-batchmode -projectPath tests/UnityFixture -executeMethod AdmissionLiveFixture.Run -logFile tests/diagnostics/admission-live.log` проверяет настоящий loopback UNet: отсутствие плагина, другую карту, успешную проверку и потерю heartbeat. Стенд подменяет создание персонажа счётчиками, чтобы не загружать пользовательский мир или сохранения. Это не заменяет проверку конкретной конфигурации хостинга и Linux runtime.
